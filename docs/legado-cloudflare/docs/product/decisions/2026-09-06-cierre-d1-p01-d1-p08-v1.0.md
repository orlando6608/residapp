# Decisión funcional: cierre de D1-P01 y D1-P08

**Identificador:** `DEC-CONNECT-2026-09-06-D1-P01-P08`  
**Versión:** 1.0  
**Fecha de aprobación:** 6 de septiembre de 2026  
**Estado:** APROBADA  
**Responsable de producto:** Promotor del proyecto / Dirección clínica  
**Ámbito:** identidad administrativa del residente y validación del estado basal  
**Datos autorizados en esta fase:** exclusivamente ficticios  

## 1. Decisión formal

Se aprueban las cuatro reglas siguientes:

1. **Catálogo de sexo documentado — `D1-P01`.** El valor procede de una fuente administrativa documentada y nunca se infiere. El catálogo persistido utiliza los códigos FHIR AdministrativeGender `male`, `female`, `other` y `unknown`, con etiquetas visibles en castellano «Hombre», «Mujer», «Otra categoría documentada» y «No consta». No se solicita texto libre ni se confunde este campo con identidad de género o sexo clínico para decisiones asistenciales.
2. **Ausencia de ayuda técnica — `D1-P08a`.** `NINGUNA` significa que consta que la persona no utiliza una ayuda técnica complementaria. `NO_DOCUMENTADO` significa que la información no se conoce o no consta. `NO_APLICA` se elimina de este campo. `OTRA` exige una descripción breve no vacía.
3. **Alimentación enteral — `D1-P08b`.** `NO_APLICA` solo puede utilizarse en textura de alimentos y consistencia de líquidos cuando la vía sea exclusivamente `ENTERAL`. Si la vía es `MIXTA`, debe registrarse la textura y la consistencia de la parte oral o `NO_DOCUMENTADO`.
4. **Descripción de opciones abiertas — `D1-P08c`.** Toda opción estructurada `OTRO` u `OTRA`, incluidas `OTRA_TEXTURA_ADAPTADA` y `OTRO_PRODUCTO_DE_APOYO`, exige una descripción breve que, tras eliminar espacios periféricos, no quede vacía. Si no se selecciona la opción abierta correspondiente, su texto debe permanecer vacío.

## 2. Reglas de implementación y prueba

- El catálogo de sexo es cerrado; se rechazan valores fuera de los cuatro códigos aprobados.
- `unknown` representa ausencia de información documentada y permite completar el alta sin inventar un dato.
- Los códigos se conservan estables en persistencia; las etiquetas visibles pueden localizarse sin cambiar el significado.
- Las reglas de ayuda técnica, vía, textura, líquidos y textos abiertos se validan tanto en dominio server-side como en la operación de firma.
- Un borrador puede estar incompleto. Una versión basal no puede firmarse si incumple alguna de estas reglas.
- La interfaz no autocorrige ni deduce valores clínicos.
- Los fixtures y pruebas usan datos exclusivamente sintéticos.

## 3. Decisiones no incluidas

`D1-P04`, `D1-P05` y `D1-P06` continúan diferidas y denegadas por defecto. No forman parte de la primera entrega y esta decisión no crea botones, endpoints, grants o capacidades para traslado/reactivación, cancelación excepcional por ausencia del creador ni inicio de rectificación.

El esquema puede preservar capacidad de extensión para esos flujos, pero dicha capacidad estructural no equivale a autorización funcional.

## 4. Impacto documental

Esta decisión completa catálogos y criterios de aceptación que la línea base v1 mantenía expresamente pendientes. Por tanto:

- exige PRD v0.5;
- exige una matriz de permisos v0.2.1 para actualizar referencias, sin cambiar permisos;
- exige wireframes v0.3 de Administración, Enfermería y Medicina;
- exige trazabilidad v0.2;
- exige la línea base incremental `LBF-CONNECT-2026-09-06-V1.1`;
- exige alinear los contratos `0001` y `0002` y el ADR `0003`.

La línea base `LBF-CONNECT-2026-09-05-V1`, su commit y su tag permanecen intactos como evidencia histórica.

## 5. Efecto sobre la migración 0001

Con `D1-P01` y `D1-P08` cerradas, se autoriza crear y aplicar `0001` únicamente sobre una D1 local desechable, con datos sintéticos, para revisar el SQL y ejecutar `DB-T01`–`DB-T16`.

No se autoriza aplicar `0001` a una D1 remota, usar datos reales, iniciar un piloto ni desplegar en producción hasta que el ADR y las puertas posteriores lo permitan expresamente.

## 6. Referencia de interoperabilidad

El catálogo administrativo se alinea con `http://hl7.org/fhir/administrative-gender`. La interoperabilidad no amplía la finalidad del dato ni autoriza inferencias.
